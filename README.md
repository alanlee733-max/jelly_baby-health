# 신생아 데일리 헬스 트래커

생후 0~2주 아기의 하루를 폰으로 기록하고, 공개된 참고 기준과 비교해 신호등으로 보여주는 개인용 앱입니다.

> **이 앱은 아기의 건강 상태를 진단하지 않습니다.**
> 표시되는 신호는 공개된 참고 기준과 입력값을 비교한 결과일 뿐입니다.
> 이상이 의심되면 반드시 소아청소년과 등 의료진과 상담하세요.
> 상담 권고 기준은 보수적으로 설정되어 있으며, 해당되지 않더라도 걱정되면 언제든 병원에 연락하는 것이 우선입니다.

## 1. 폰에서 쓰기 (GitHub Pages)

### 1단계 — 사이트 켜기

1. GitHub 에서 이 저장소를 엽니다.
2. 위쪽 **Settings** 탭을 누릅니다.
3. 왼쪽 메뉴에서 **Pages** 를 누릅니다.
4. **Build and deployment → Source** 를 `Deploy from a branch` 로 둡니다.
5. **Branch** 에서 배포할 가지를 고릅니다.
   - 작업 내용을 `main` 에 합쳤다면 → `main` / `/ (root)`
   - 아직 안 합쳤다면 → `claude/newborn-health-tracker-vz3lj1` / `/ (root)`
6. **Save** 를 누르고 1~2분 기다립니다.
7. 같은 화면 위쪽에 주소가 나타납니다. 보통 이런 모양입니다.

```
https://alanlee733-max.github.io/jelly_baby-health/
```

### 2단계 — 폰 홈 화면에 추가

그 주소를 폰 브라우저로 엽니다.

- **아이폰 (사파리)**: 아래 **공유 버튼(↑)** → **홈 화면에 추가**
- **안드로이드 (크롬)**: 오른쪽 위 **⋮** → **홈 화면에 추가** 또는 **앱 설치**

홈 화면 아이콘으로 열면 주소창 없이 앱처럼 뜨고, 한 번 연 뒤에는 **인터넷이 끊겨도 열립니다.**
새벽에 지하나 비행기모드에서도 기록할 수 있습니다.

### 처음 실행하면

아기 정보(이름 · 생년월일 · 출생 체중 · 수유 방식)를 한 번 입력합니다.
이 정보는 나중에 홈 화면 오른쪽 위 **설정** 에서 언제든 고칠 수 있습니다.

## 2. 기록은 어디에 저장되나요

**기록은 인터넷으로 전송되지 않습니다.** 앱을 연 그 폰의 브라우저 안(localStorage)에만 저장됩니다.
GitHub 에도, 다른 어떤 서버에도 올라가지 않습니다.

그래서 주의할 점이 있습니다.

- 브라우저의 **인터넷 사용 기록 / 사이트 데이터를 지우면 기록도 같이 사라집니다.**
- 폰을 바꾸면 기록은 따라가지 않습니다.
- 아이폰 사파리는 오래 안 쓴 사이트의 데이터를 정리하기도 합니다.

**그래서 가끔 백업해 두세요.** 홈 화면 → **설정** 화면 아래쪽에 있습니다.

- **기록 내보내기** — 전체 기록을 JSON 파일 하나로 저장합니다.
- **기록 불러오기** — 그 파일을 다시 읽어옵니다. (새 폰으로 옮길 때 사용)

저장소를 public 으로 두면 **앱 코드는 누구나 볼 수 있지만, 아기 기록은 볼 수 없습니다.** 기록은 폰 안에만 있기 때문입니다.

## 3. 판정 기준 고치기 — `criteria.json`

이 앱의 모든 기준값·문구·출처는 **`criteria.json` 파일 한 곳**에 있습니다.
코드에는 기준 숫자가 하나도 없습니다. 기준을 바꾸려면 이 파일만 고치면 됩니다.

예를 들어 젖은 기저귀 기준을 생후 5일부터 6개 → 7개로 올리려면:

```json
"wetDiapers": {
  "minByDayOfLife": { "1": 1, "2": 2, "3": 3, "4": 4, "5plus": 7 }
}
```

이 한 글자만 고치면

- 홈 화면 판정 문구가 `(생후 12일 기준 최소 7개)` 로 바뀌고
- 추이 그래프의 기준선도 따라 올라가고
- **이미 적어둔 과거 기록도 전부 새 기준으로 다시 평가됩니다.**

판정 결과를 저장해두지 않고 화면을 그릴 때마다 다시 계산하기 때문입니다.

고칠 수 있는 것들:

| 고치고 싶은 것 | 위치 |
|---|---|
| 수유 횟수 기준 | `categories.feeding.thresholds` |
| 기저귀 기준 | `categories.wetDiapers.minByDayOfLife` |
| 대변 색 추가·삭제, 색별 신호 | `categories.stool.colors` |
| 체중 감소율 기준 | `categories.weight.thresholds` |
| 체온 범위 | `categories.temperature.thresholds` |
| 황달 단계별 신호 | `categories.jaundice.levels` |
| 즉시 상담 신호 목록 | `generalRedFlags.items` |
| 하루 총계 항목을 몇 시부터 판정할지 | `partialDay.cutoffHour` |
| 출처 링크 | `sources` |
| 기준 버전·검토일 | `version`, `lastReviewed` |

대변 색이나 증상 항목을 **추가하면 앱 화면의 선택지도 자동으로 늘어납니다.** 화면을 따로 고칠 필요가 없습니다.

### 고친 뒤 확인하기 (선택)

컴퓨터에 Node.js 가 있다면, 고친 기준이 로직과 어긋나지 않는지 한 줄로 확인할 수 있습니다.

```bash
node test-evaluate.js
```

여러 상황의 판정 결과가 표로 나오고, 맨 아래에 `PASS` 목록이 나옵니다.
**`FAIL` 이 하나라도 있으면** 기준 파일과 판정 로직이 맞지 않는 것입니다.

## 4. 내 컴퓨터에서 열어보기

`index.html` 을 **더블클릭해서 여는 것은 동작하지 않습니다.**
브라우저 보안 정책 때문에 `criteria.json` 을 읽지 못합니다. (그 경우 앱이 한국어로 안내를 띄웁니다.)

작은 웹서버로 열어야 합니다. 이 폴더에서 터미널을 열고 아래 한 줄을 실행한 뒤,

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000` 으로 접속합니다.
(Node.js 를 쓰신다면 `npx serve` 도 같습니다.)

## 5. 화면 구성

- **홈** — 아기 이름 / 생후 N일 / 오늘 날짜 → 신호등 한 줄 → 판정 카드(빨강·노랑이 위로) → 오늘 기록하기 → 주의사항
- **오늘** — 날짜를 앞뒤로 옮기며 기록합니다(미래는 볼 수 없음). 입력하는 동안 각 섹션 제목 옆의 점이 실시간으로 색이 바뀝니다.
- **추이** — 체중 / 젖은 기저귀 / 수유 / 체온 그래프. 점 색은 그날의 신호이고, 아래 스트립의 날짜를 누르면 그날 기록으로 갑니다. 체중은 며칠 간격으로 재도 잰 날끼리 잇되 **기록이 없는 구간은 흐린 점선**으로 그립니다(그 사이를 아는 것처럼 보이지 않도록). 횟수 그래프는 기록이 없는 날에서 선을 끊습니다.
- **근거** — 주의사항 전문, 항목별 참고 기준과 출처 링크, 기준 버전과 검토일

**저장 버튼을 깜빡해도 괜찮습니다.** 화면을 옮기거나 날짜를 넘기거나 앱을 내려놓으면 입력하던 내용이 자동으로 저장됩니다.

### 모르는 값은 `—` 로 두세요

수유·기저귀·대변 횟수는 처음에 **`—`(모름)** 으로 시작합니다.

- `+` 를 누르면 1, `−` 를 누르면 0 부터 시작합니다
- **손대지 않으면 `—` 그대로 남고, 판정하지 않습니다** ("아직 입력하지 않음" 으로만 표시)
- 실제로 0회였던 날은 `−` 를 눌러 **0** 으로 명시하세요 (대변 0회 판정은 그때 동작합니다)
- 잘못 눌렀으면 **숫자를 누르면** 다시 `—` 로 돌아갑니다

조리원처럼 기록이 없던 기간이나, 기록을 시작한 첫날의 일부 시간대를 **0 으로 저장해서 "부족" 으로 보이지 않게** 하기 위한 구분입니다. 지난 날짜로 돌아가 **체중만** 적어두는 것도 됩니다 — 나머지는 `—` 로 남아 판정되지 않고, 체중 추이 그래프에는 점이 찍힙니다.

### "집계 중" 표시

수유·기저귀처럼 **하루 총계로 비교하는 항목**은 아침에 아직 못 채운 것이 당연합니다. 오전 10시에 수유 2회를 "부족"이라고 표시하면 매일 아침 빨간 화면을 보게 되므로, 오늘 하루가 진행 중인 동안에는 지금까지의 횟수만 보여주고 **밤 9시부터 기준과 비교**합니다. 시각은 `criteria.json` 의 `partialDay.cutoffHour` 에서 바꿀 수 있습니다.

시간과 무관한 항목은 **보류하지 않습니다.** 대변 색(흰 변·혈변), 체온, 체중, 황달, 활력, 그리고 즉시 상담 신호 체크는 오전이든 새벽이든 즉시 판정합니다. 대변은 색·형태는 그대로 보고, "0회"라는 횟수 판정만 미룹니다.

어제 이전 기록은 시각과 관계없이 항상 그대로 판정합니다.

## 6. 파일 구조

```
index.html        화면 하나에 섹션 5개 (설정/홈/오늘/추이/근거)
style.css         어두운 테마, 터치 타겟 48px 이상
criteria.json     ★ 판정 기준 · 문구 · 출처. 고칠 곳은 여기입니다
evaluate.js       판정 로직. 순수 함수 evaluate(log, baby, criteria, now)
chart.js          SVG 그래프와 추이 화면
app.js            저장 · 화면 전환 · 홈 · 오늘 화면
manifest.json     홈 화면 추가용 앱 정보
sw.js             오프라인 동작 (서비스워커)
icons/            앱 아이콘 192 · 512
test-evaluate.js  판정 로직 검증 (앱에는 포함되지 않음)
```

빌드 도구도, 프레임워크도, 외부 라이브러리도 쓰지 않습니다. 파일을 그대로 열면 그게 앱입니다.

### 저장 형식

```
nt:baby              { name, birthDate, birthWeight, feedingType }
nt:log:2026-09-12    그날의 기록 한 건
```

**판정 결과(빨강/노랑/초록)는 저장하지 않습니다.** 항상 다시 계산합니다.

## 7. 앱을 고쳤는데 폰에서 그대로예요

**온라인이면 앱을 열 때마다 최신 파일을 받습니다.** 고친 내용은 다음에 앱을 열면 바로 보입니다.
(캐시는 오프라인용 사본으로만 씁니다. 네트워크가 2.5초 안에 응답하지 않으면 사본을 먼저 보여줍니다.)

지금 폰에 어떤 버전이 깔려 있는지는 **근거 화면 맨 아래 "앱 빌드"** 에서 확인할 수 있습니다.

그래도 안 바뀌면 `sw.js` 첫 부분의 숫자를 올려 다시 배포하세요. 서비스워커 자체가 바뀌었다는 신호가 되어 확실히 갱신됩니다.

```js
const CACHE_VERSION = 'v3';   →   const CACHE_VERSION = 'v4';
```

⚠️ **사파리의 "웹사이트 데이터 지우기"로 해결하려 하지 마세요.** 아기 기록이 함께 지워집니다. 꼭 필요하면 설정 화면에서 **기록 내보내기**를 먼저 하세요.

## 8. 지금 버전이 다루지 않는 것

- 생후 2주까지를 기준으로 만들었습니다. 그 이후 기준은 `criteria.json` 에 없습니다.
- 수면은 기록·그래프만 하고 판정하지 않습니다. `criteria.json` 의 `sleep` 에 기준값이 없기 때문입니다.
- 하루 총계 항목(수유·기저귀·대변 횟수)은 밤 9시부터 판정합니다. 그 전에는 "집계 중"으로만 보입니다.
- 아기 한 명만 기록합니다.
- 기록이 없던 기간(예: 조리원)은 비워두면 됩니다. 그 날짜에 아는 값(체중 등)만 적어둘 수 있습니다.
